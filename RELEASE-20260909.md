## Changes

- Explicit dark text and icon colors in the white service-choice sheet. The
  previous system-default text color could disappear against white on Android.
- Services first, dark service-icon tiles, a single compact order summary below
  the service grid, and a separate Orders tab with Active and History views.
- Smaller booking headings and a collapsed saved-device selector with a new-device
  option. Device labels avoid duplicate brand prefixes such as HP HP Pavilion.
  No real customer devices were deleted or renamed.
- A fresh query cache and navigation tree for each signed-in account. Credential
  changes are serialized; late refreshes and responses from an old session are
  rejected. Public authentication calls no longer inherit the old session's refresh
  behavior. The greeting uses the authenticated user's name, not a hardcoded name.
- Fixed missing ownership validation on GET /devices/:id. Customer lists were
  already scoped by authenticated user; the individual detail route now enforces
  ownership too. No historical-access audit was performed.
- Forgot password screen with a six-digit email-code reset flow. Codes expire in
  ten minutes, are HMAC-protected in the database, have five attempts and a
  persistent 60-second resend cooldown. Successful reset atomically consumes the
  challenge and revokes access and refresh sessions through token_version.
- Added private password_resets table and users.token_version without deleting
  customer records. RLS is enabled and public API roles have no table grants.
- Android uses native FCM tokens and the existing backend Firebase credentials.
  Tokens are detached from an old account when registered to a different account.
- Mobile Alerts includes permission/registration status, enable, system settings
  and a rate-limited test action. Tests report provider acceptance, not guaranteed
  physical delivery. Invalid native tokens are cleared after a provider rejection.
- Admin re-registers an existing authorized browser subscription when its server
  record was removed by logout, instead of silently treating it as working.
